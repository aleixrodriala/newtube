Explicit exclusions and remaining gaps:

- **SABR source/metadata/seek/EOS/CDN work is not production parity.** This port
  does not have a production Media3 SABR source. The separate protocol/decoder
  proof stays in test builds. The upstream backoff patch `66cf8bb` was itself
  removed by `893e08a`; it is not a current fix to port.
- **Alternate formats after service refusal (`0b01a017`) were not imported.**
  They do not establish a speed improvement and are not reconciled with this
  port's terminal-denial and cancellation contracts. No new denial bypass,
  credential mechanism or service identity policy is introduced by this release review.
- **Rx queue bounding (`bc67a7e`/`86f0327`) is not copied verbatim.** Its
  caller-runs saturation policy can put blocking service work on the UI thread;
  a safe replacement needs a separate scheduling design.
- **Playlist title-based identity reuse (`0b66e615`) remains deferred.** It can
  merge distinct same-named playlists. The initial-cache correctness fix is
  included without introducing that ambiguity. This is not described as full
  playlist-cache parity.
- TV remote key mappings, Android 4.4 compatibility, cutout-grid layout,
  multidex keep lists and TV-only settings/translations do not map directly to
  the phone-only Media3 build. Playback-speed additions are enhancements rather
  than a playback/network bug fix and were not folded into this release review.

## Validation and limitations

- **468 unit/Robolectric tests across 61 suites passed**, with no failures,
  errors or skips: all app/common tests plus the selected offline dependency
  regressions. **49 host benchmark/lifecycle tests passed.** This release review
  adds 18 tests for title refresh, history/cache bookkeeping and seek buffering.
- Final debug and signed release assembly passed, including
  `lintVitalStmobileRelease`. APK package/version, ARM64 ABI, signing certificate
  and on-device SHA-256 were checked. Release is not debuggable; compiled baseline
  profiles are present and the local fixture asset is absent.
- Pixel 9: in-place upgrade from 1.7.0 to the exact signed ARM64 artifact passed
  at 01:06:55 CEST with account/app data retained. Normal playback on validated,
  metered cellular rendered video and metadata, progressed beyond three minutes,
  and resumed after a seek to about eight minutes. A backward seek while paused
  returned to PAUSED at 154.821 seconds and stayed paused. The app was then
  returned to Browse with no playback running. One initial media 403 followed
  by the existing automatic recovery was observed; this is not a zero-error claim
  or a controlled startup comparison. No network, quality, account or experiment
  settings were changed. The initial unscoped shell URL opened the default video
  app; that attempt is excluded. The corrected app-scoped intent is the release
  playback smoke check.
- Release assembly runs its critical `lintVitalStmobileRelease` checks.
  **Full `lintStmobileRelease` is not green:** it reports 94 existing errors in
  unchanged UI/resources (82 MissingTranslation, 6 UseAppTint, 4
  StringFormatMatches and 2 WrongConstant), plus 296 warnings. No baseline or
  broad suppression was added to conceal this. These are separate from unit-test
  and release-critical lint results.
- The preceding [Pixel startup comparison](../mobile-port/PIXEL-STARTUP-ABR-2026-09-07.md)
  and [release-profile benchmark](../mobile-port/RELEASE-BENCHMARK-2026-09-08.md)
  provide performance evidence; a final release smoke test is not a new paired
  speed measurement. Direct cellular evidence includes LTE/5G NSA, not forced LTE.
- Normal settings keep speculative next-media sample preload **off**. The live
  acceptance probe returned a refusal and no preload hit. Baseline-profile
  inclusion has been verified, but its timing benefit remains unproven.
- Account-only playback, some 403/server refusals, and server history can still
  fail. New SmartTube receiver priority has offline and Pixel-UI coverage, but
  still needs real TV-code pairing/playback acceptance.
